Section 01

Why This Matters

Access provisioning is the #1 cause of timeline delays in Azure/M365 integration projects. This document lists exactly what's needed, when it's needed, and why — so there are no surprises on day one.

!
Pre-Kickoff Blockers

Items marked with ⚠ are hard blockers — work cannot begin on that phase without them. Ideally, all Section 02 items are ready before Day 1. If your organization requires IT tickets or approval workflows for access provisioning, please start those now.

i
How to Share Credentials

Never send secrets via email. Use a secure channel: a shared 1Password/Bitwarden vault, Azure Key Vault direct access, or an encrypted message via Teams. Temporary passwords should be rotated after first use. All credentials will be stored in Azure Key Vault once infrastructure is provisioned.

$
Azure Consumption Costs

All Azure resources (Cosmos DB, AI Search, Container Apps, OpenAI tokens, Service Bus, etc.) run in your subscription and are billed to your Azure account. Estimated MVP monthly cost is $150–$300 depending on document volume and query frequency. I'll configure the lowest viable SKUs and can provide a cost estimate before provisioning. My development fee is separate from Azure infrastructure costs.

Azure Subscription Access

I need the ability to create and manage Azure resources in your subscription. The simplest way is to invite me as a guest user to your Entra ID tenant and assign a role on the target resource group. This takes about 5 minutes from your IT admin.

Option A — Guest invite (recommended) Your IT admin invites my email as a B2B guest user in Entra ID, then assigns Contributor role on the resource group. I receive an email invite, accept it, and I'm in. Fastest path — takes ~5 minutes.
Option B — Dedicated tenant account Your admin creates a full user account for me in your tenant (e.g. roman@yourcompany.com), assigns Contributor on the resource group, and sends me the temporary password. I sign in and reset it. Avoids conditional access issues that some tenants have with guest accounts.
Resources I'll create Resource Group, Key Vault, Container Registry, Container Apps, Cosmos DB, Service Bus, AI Search, Log Analytics — all within a single resource group
⚠ Azure Region All resources are deployed to a single Azure region. You must confirm the region before Day 1 — it cannot be changed after deployment. Consider: (a) data residency / compliance requirements, (b) proximity to your users for lowest latency. I'll verify that Azure OpenAI models are available in the chosen region. Common choices: East US, West Europe, Sweden Central.
Terraform state backend Terraform needs a Storage Account to store its state file. I'll create this manually as the first step on Day 1 (before terraform apply). No client action needed — just be aware a small Storage Account will appear in the subscription.
When needed ⚠ Before Day 1 — hard blocker for P0

Microsoft Entra ID (Azure AD) — App Registration

I need to register an application in your Entra ID tenant. This app will authenticate to Microsoft Graph to access SharePoint files and receive change notifications. It requires Application Registrations → New registration permission, or your IT admin creates the app and shares the credentials.

The registered app will need the following Microsoft Graph API permissions (application type, not delegated):

Graph Permissions Required Sites.Read.All · Files.Read.All · Subscriptions.ReadWrite.All (for change notifications)
Admin Consent ⚠ A Global Administrator or Privileged Role Administrator must grant admin consent for the above permissions
What I need from the app Application (client) ID · Directory (tenant) ID · Client secret or certificate
When needed ⚠ Before Day 3 — hard blocker for P1. Ideally ready at kickoff since admin consent can take 24–48h in some organizations.

Azure OpenAI — Models & Deployment

The document pipeline uses Azure OpenAI for embeddings and the RAG API uses a chat model for answer generation. I handle the full setup — creating the Azure OpenAI resource and deploying the models is part of the sprint (P0/P2). No action needed from your side unless your organization restricts Cognitive Services creation.

Default path (recommended) I create the Azure OpenAI resource via Terraform in P0, then deploy models through the AI Foundry portal (ai.azure.com) at the start of P2. The portal lets me check regional quota availability in real time and pick the best region. No client action needed — Contributor role covers this.
Models I'll deploy text-embedding-3-large (for chunked document embeddings) + gpt-4o-mini (for RAG answer generation). Can upgrade to gpt-4o if budget allows.
Alternative — if restricted If your organization restricts who can create Cognitive Services / OpenAI resources, your admin creates the resource and deploys the two models above. Then share the endpoint URL and API key (or grant my account Cognitive Services User role on the resource).
Subscription type Standard Azure OpenAI models (GPT-4o, text-embedding-3-large) are available to all Azure customers with a paid subscription — no separate approval form required. Pay-As-You-Go or Enterprise Agreement both work. Free Trial may have limitations.
When needed Resource created in P0. Models deployed before Day 6 (start of P2). If restricted, share endpoint + key or grant access by Day 6.

Section 05

Security & Data Handling

How credentials and data are handled during and after the engagement.

🔒 Secrets in Key Vault Only

All credentials (Graph app secrets, API keys, connection strings) are stored exclusively in Azure Key Vault from Day 1. No secrets in code, environment variables, config files, or chat messages after initial handoff.

🔑 Managed Identities

All Azure services (App Service, Container Apps, workers) authenticate to Key Vault and each other using managed identities — no service account passwords to manage or rotate.

📋 Least Privilege

Each service gets only the permissions it needs. The document worker reads SharePoint files. The RAG API queries AI Search. No service has broader access than its function requires.

🚪 Access Revocation

At project close, my personal access (Azure Contributor, Entra ID, Teams) is revoked. The application continues to run using its own managed identity — zero dependency on my account post-handoff.

📝 Audit Trail

Azure Activity Log records every resource change I make. Key Vault access logs track every secret read. Full transparency throughout the engagement.

🗑️ Client Secret Rotation

If a client secret was created for the Entra ID app, I recommend rotating it after project close. The new secret is updated in Key Vault — the application picks it up automatically.
