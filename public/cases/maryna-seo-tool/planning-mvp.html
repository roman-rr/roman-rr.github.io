Phase Details

Each phase has a clear objective and exit criteria. Nothing moves to the next phase until the gate conditions are met.

P0Phase 0 · ~3 hours

Setup + Hosting + Database Foundation

Initialize the project repository with a clean structure (api/, frontend/, docker/) and commit the initial Python + FastAPI scaffold. Provision the hosting environment (Cloud Run, Render, or similar — your preference) plus a managed database for report metadata and idempotency cache. Environment variables locked in for the upcoming SEO API keys + shared password. I deploy and verify the foundation end-to-end before feature development starts — your team doesn't need to validate anything technical.

3hours
P1Phase 1 · ~10 hours

SimilarWeb + SEMrush + SEOptimer API Integrations

Build clean Python clients for each of the three SEO services. Each client handles authentication, rate-limit awareness, error handling, and retries. SEOptimer is the primary source for technical / UX data (per your spec) — pulling the full audit response with all subsections. SimilarWeb handles traffic, sources, and engagement metrics. SEMrush handles keywords, rankings, visibility, and backlinks. A 24-hour cache layer prevents re-querying the same URL within that window — saves real API spend on repeat audits and powers idempotency.

10hours
P2Phase 2 · ~12 hours

Data Processing + Rule-Based Issue Engine

This is the value-bearing layer. The three SEO APIs already detect their own issues — SEOptimer flags technical and UX problems, SEMrush surfaces keyword and backlink gaps, SimilarWeb shows engagement weaknesses. The processing layer combines all three into a unified structure, then runs a set of mapping and prioritization rules over the result:

  • • Normalize — every issue (regardless of source API) mapped to our standard schema: title, business-focused description, severity, impact range, recommendation
  • • Rewrite — SEOptimer raw text rewritten into business-focused descriptions via templated phrasing (Sprint 4 upgrades this to LLM-driven rewriting)
  • • Severity mapping — API severity → our Low / Med / High scale
  • • Impact ranges — issue type mapped to estimated business impact (e.g. "Slow website → +10–25% conversion potential")
  • • Priority scoring — severity × impact → priority score, used for ranking
  • • Filter to top 10–15 — only the most impactful issues kept; the report doesn't drown the reader
  • • Total Growth Potential — individual impact ranges combined into a single headline metric

By the end of this phase, any URL run through the system produces a clean, structured JSON of business insights ready for PDF rendering.

12hours
P3Phase 3 · ~10 hours

PDF Report Generation + Storage Layer

Build the HTML report template — clean, functional, structured to match your spec sections (cover page, executive summary, traffic analysis, SEO analysis, technical & UX, key problems, recommendations). Visual polish to match SEO-Report (3).pdf brand fidelity comes Sprint 2. Playwright runs headless to convert the HTML (with injected data) to PDF in real time. Generated PDFs are saved to storage with metadata (URL, generation date, business type) so they're available for re-download anytime — no need to regenerate.

10hours
P4Phase 4 · ~6 hours

Web Form + Password Gate + Recent Reports List

Single web page with a URL input, optional business-type dropdown, and "Generate Report" button. Single shared password protects access — your team uses one password to log in. After clicking generate: a loading state appears (5–30 seconds depending on API responses), then the PDF downloads automatically. A "recent reports" list shows the last N generated PDFs with URL, date, and re-download links. Multi-user login + per-user access control comes Sprint 3.

6hours
P5Phase 5 · ~8 hours

Hardening + Edge-Case Testing + Retention + Demo

Run 5–10 real client URLs through the full flow end-to-end. Catch and fix edge cases — large sites, sites with SEOptimer errors, invalid URLs, API timeouts, duplicate submissions. Polish error messages so non-technical users see helpful messages, not technical traces. Configurable retention policy locked in (default 30 days, PDFs auto-archive after that). Production deployment with environment variables verified. A short demo walkthrough document so anyone on your team is productive after a 5-minute read. Final sign-off marks Sprint 1 close.

8hours
